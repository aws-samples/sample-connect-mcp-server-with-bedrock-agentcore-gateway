# x402 MCP probe — civicteam/x402-mcp (Base Sepolia)

**Date:** 2026-09-01
**Endpoint:** `https://x402-mcp.fly.dev/mcp` (hosted demo, Base Sepolia testnet)
**Purpose:** Sample the real 402 challenge shape from an x402-protected MCP server, to design the
AgentCore payer's MCP-transport payment wrapper. No secrets here.

## Transport

Streamable-HTTP MCP. `tools/list` is free; `tools/call` on a paid tool returns **HTTP 402** at the
transport level (not inside a tool result). Request needs
`accept: application/json, text/event-stream`.

## Design implications for the AgentCore payer

- **Version is v1** → present proof in `X-PAYMENT` header, flat proof shape (top-level
  `scheme`/`network`). Still auto-detect `x402Version` — AgentPay's real MCP may differ.
- **Intercept at the MCP HTTP transport**: on 402 from a `tools/call` POST, read the challenge from
  the JSON body, call `ProcessPayment`, retry the same POST with `X-PAYMENT` on a fresh httpx client.
- **Network mapping gotcha**: challenge `network` is the human label `base-sepolia`; `ProcessPayment`
  input requires **CAIP-2** (`eip155:84532`); the v1 proof presented to the merchant uses
  `base-sepolia` again. Convert both directions.
- `asset` `0x036CbD…` is the canonical Base Sepolia USDC address; `maxAmountRequired` is in USDC base
  units (6 decimals), so `1000` = $0.001.
- The civic demo signs client-side with its own `PRIVATE_KEY`; the AgentCore payer does NOT — replace
  that signing step with `ProcessPayment`.
