THE SERVICE · GENERALLY AVAILABLE

托管服务提供什么

01 · WALLETS

嵌入式钱包

把终端用户连到 Coinbase CDP 或 Stripe(Privy) 的嵌入式钱包,用稳定币付款。

02 · ORCHESTRATION

一次 ProcessPayment

限额校验 → 网络解析 → 构造交易 → 签名 → 出证明。支持 x402 与 MPP。

03 · LIMITS

预算与护栏

会话级 availableSpendAmount 与 expiryTimeInMinutes(15–480);并发下原子预留,限额不会被突破。

04 · OBSERVABILITY

花了多少,花在哪

CloudWatch 指标:成功/失败次数、时延、花费金额,按 payment manager 与资源 ARN 归因。

05 · PROVIDER-AGNOSTIC

换 provider 不改 agent

钱包提供商、区块链网络、支付协议三个维度都收在服务内部,agent 代码只调一个 API。

06 · KEYS STAY OUT

agent 不持私钥

凭证存在 AgentCore Identity 的 Payment Credential Provider,签名在服务端完成——agent 拿到的只是一张证明。

HOW IT WORKS · RESOURCES

六个组件各管什么

前三个在控制面,建一次就不用再碰;后三个在数据面,每个用户、每次运行、每次调用都会用到。

CONTROL
PaymentManager

账号里的支付权威:一切支付操作的顶层资源与配置边界。

CONTROL
PaymentConnector

连到具体钱包提供商的配置:Coinbase CDP 或 Stripe(Privy)。

IDENTITY
CredentialProvider

AgentCore Identity 里的专用凭证库,存 provider 密钥——不进环境变量。

DATA · PER USER
PaymentInstrument

每个用户一个嵌入式钱包,绑定一条链;agent 代表该用户付款。

DATA · PER RUN
PaymentSession

一次交互的支出上下文:可设预算与过期时间(15–480 分钟)。

DATA · PER CALL
ProcessPayment

真正干活的那个:校验限额、解析网络、构造并签名交易、返回支付证明。

Control plane once · data plane per user, per run, per call06 / 10

MERCHANTS · A PAID MCP MARKETPLACE

Merchants 怎么做

没有注册流程、没有 API key、没有配额表——定价只是路由上的一个数字。

01 · SERVE MCP

工具做成 MCP server

实现 initialize / tools/list / tools/call;inputSchema 写清楚,Buyers 的 agent 靠它读懂怎么调。

02 · PRICE THE ROUTE

付费路由前挂 x402

中间件放在业务逻辑之前,定价就是一个数字;未付款先回 402 + challenge。

03 · 402 IN THE PAYLOAD

challenge 与证明都走 MCP 载荷

challenge 放 structuredContent,并接受 headers 参数带回证明——Gateway 转发参数但不能注入 HTTP 头,这是能穿过它的唯一办法。

04 · BE DISCOVERABLE

挂成 Gateway target

建 mcpServer target 指向你的 /mcp;任何接入该 Gateway 的 agent tools/list 就能发现你。

05 · GET PAID

收款地址备好稳定币账户

payTo 要能接收 USDC(链上没有对应代币账户时,结算会一直失败)。测试网先用 Base Sepolia 或 Solana devnet。

06 · ONE IMPLEMENTATION

人和 agent 共用一套

人走 HTTP、agent 走 MCP,而定价、校验、结算只有一份代码——不会分裂成两套各自漂移的逻辑。
